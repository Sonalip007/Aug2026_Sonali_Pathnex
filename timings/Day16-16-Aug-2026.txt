Flow of kubernetes cluster:
AWS + Kubernetes application architecture
Internet --> Route 53 --> Load Balancer --> Ingress --> / or .api based on that front end & backend
-User hits https://pathnex.come from internet--> it will come to Route 53
-route53 do DNS resolution & from route53 requets comes to load balancer (LB is public entry point to your application)
-Then Ingress comes in to picture. It contains routing rules e.g. / : frontend & /api : backend
-so request with / goes to frontend cluster Ip & with /api goes to backend ip (it do pathbased routing)
-frontend is kubernetes service type of clusterIP which job is to provide a stable endpoint for front end pods. 
The Service distributes traffic between those Pods. how pods communicate internally? using clusterIP
- Backend ClusterIP Service: provides a stable internal endpoint for the backend Pods.
Backend talks to MongoDB/ database. Your backend application needs to store/retrieve data.
- MongoDB uses a Headless Service
why headless service as database uses statefulset
