Installed prometheus using helm chart : think of Prometheus as a monitoring system for your cluster.
Prometheus collects metrics (numbers about what's happening) from your Kubernetes cluster and applications.
Prometheus collects these numbers and stores them as time-series data

Helm is the package manager for Kubernetes.
Instead of manually creating dozens of Kubernetes YAML files, you can install a package called a Helm chart
helm install prometheus prometheus-community/prometheus
which means : "Helm, install the Prometheus Kubernetes package into my cluster."

The Prometheus Helm chart creates the Kubernetes resources needed to run Prometheus
Prometheus = collects/stores metrics

Grafana = visualizes those metrics

Helm = installs/manages the Kubernetes packages

Helm is a tool used to manage Kubernetes applications.  Helm 4 is now the current major release
It simplifies process of deploying, configuring & maintaing complex applications on kubernetes cluster
It is like package manager for kubernetes like we have pip for python

Helm chart has all yaml files : Deployment, services, ingress, secrets, pvc etc. it will look like :
my-app/
├── Chart.yaml
├── values.yaml
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── configmap.yaml
│   └── ingress.yaml
└── charts/

we can create chart with command : helm create my-app

Will see chart & values one by one 

1. Chart yaml
In this Chart.yaml describes the chart itself.

apiVersion: v2   <-- Indicates API version
name: my-app     <-- chart name 
description: My Kubernetes application  <-- Human readable description 
type: application
version: 1.0.0   <-- Chart Version
appVersion: "2.5.0" <-- App Version

apiVersion: v2 This means you're using Helm chart API version 2

2. values.yaml
This is where Helm becomes really powerful. Suppose your Deployment contains 3 replicas but in development you want 1 replica & production 5 replicas
then Instead of hardcoding:replicas: 3  you put: replicaCount: 3. inside values.yaml --> replicas: {{ .Values.replicaCount }}

Now suppose I have the same application.In development I want:1 copy in production i want 10 copies. 
Do I want to create two completely different applications?  -- No
I want one application, but with different settings. thats where values.yaml helps 

Think of it as a settings file.
values.yaml
number of copies = 10
app version = 1.5
CPU = 500
memory = 1GB
you will just write how many values you want. I want 10 copies of my application running

in simple words: 
chart.yaml has version . it has chart versions 
Value. yaml has data of values available for that version .. mhanje chart.yaml madhey aslelya version chya veli mazi value kay hoti
kiti replica set hote kiti memory hoti he sagla values.yaml madhey asta. It has application values

3. Template : 
Suppose your Kubernetes YAML says replicas: 10 But we don't want to hardcode 10. we want it should be based on user provided number 
In this case helm let us write --> replicas: {{ .Values.replicaCount }}

4. release : When we install a chart, the installed instance is called a Release.
suppose I have helm chart named my-app, so release is actual output created from my-app

helpers.tpl:
-It's a helper file where we define reusable template logic so that we don't repeat the same code across Deployment, 
Service, Ingress, and other templates."
