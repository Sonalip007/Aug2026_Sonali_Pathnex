Secure Sockets Layer : SSL is a security technology that protects the communication between your computer and a server.
SO when you open a website SSL/TLS makes this communication secure.
Without security: Someone who manages to intercept the communication could potentially see sensitive information.
An SSL certificate helps prove that you are communicating with the correct server and allows the connection to be encrypted.
With SSL/TLS: The communication is encrypted.

-Imagine you are sending a private letter to your friend. You don't want someone sitting in between you and your friend to:
Read the letter 👀, Change the letter ✏️ Pretend to be your friend 🎭
SSL helps create a secure connection between two systems.


Q.What does SSL actually provide?
1. Encryption 🔐
It converts readable information into protected/encrypted information while it travels.
2. Authentication 
SSL/TLS helps you verify: "Am I really communicating with the correct server?"
3. Data Integrity : SSL/TLS helps ensure that the data wasn't modified while travelling.
for eg. you send transfer Rs1,000 the attacker shouldn't be silently able to chnage it to Rs10,000. TLS includes mechanisms that help detect tampering.

Q.Who issues certificate ?
Certificates are generally issued by trusted organizations called: Certificate Authorities (CA) ex. Digicert, Let's Encrypt, Global Sign
Think of a CA like a trusted authority that verifies identities and signs certificates.
Your browser/operating system already contains a list of trusted root CAs.

-we can create our own certificate as well called Self-signed certificate
But the browser will usually say: ⚠️ Certificate not trusted... beacuse that certificate can be used internally. 
because nobody trusted your certificate authority.
The CA isn't the only entity capable of technically creating a certificate. CAs are trusted authorities whose signatures
browsers and operating systems recognize

Creating a Self-Signed SSL Certificate procedure: 
OpenSSL installed (default on most Linux/macOS; install manually on Windows)
• Terminal/command prompt access

1. Generate a Private Key
bash
openssl genrsa -out mysite.key 2048

2. Generate a Certificate Signing Request (CSR) <- this is like filling form
bash
openssl req -new -key mysite.key -out mysite.csr
Fill in details like:
• Common Name (use localhost or your dev domain)
• Country, State, Org, etc.

3. Generate the Self-Signed Certificate
bash
openssl x509 -req -days 365 -in mysite.csr -signkey mysite.key -out
mysite.crt

You now have:
• mysite.key – your private key
• mysite.crt – your certificate

The one who create certificate, it has private key always.
You can use it for internal access only. Not trusted by browsers by default (causes warnings).Not recommended for public-facing websites


-So if certificate expired, your browser will say Your connection is not private or NET::ERR_CERT_DATE_INVALID
it basically saying "This certificate is no longer valid, so I cannot confidently trust it."

Q.How HTTPS/TLS Connection Happens
Client                         Server
  |                              |
  | ------ ClientHello --------> |
  |                              |
  | <----- ServerHello --------- |
  |                              |
  | <------ Certificate -------- |
  |                              |
  | ---- Verification -------->  |
  |                              |
  | === Secure session setup === |
  |                              |
  | 🔐 Encrypted communication  |
  | <==========================> |
  
Step 1 : Client says: “I want to establish a secure connection.”
Step 2 : Server responds with its TLS information and certificate.
Step 3 : Client verifies the certificate.

It checks things such as:
Is it expired?
Is the domain correct?
Is the certificate trusted?
Is the certificate chain valid?

Step 4 : The client and server establish cryptographic keys for the session.
Step 5 : Now application data can be exchanged securely.

- Symmetric vs Asymmetric Encryption:
Asymmetric : Uses Public Key & Private Key - Useful for authentication/key establishment.
 Symmetric : Uses a shared Session Key - Once the secure session is established, symmetric cryptography is 
generally used because it is much faster for bulk data.

Q What is mTLS?

Normal TLS:
Client ───────→ Server
        Server
      authenticates

mTLS:

Client ───────→ Server
   ↕              ↕
Certificate    Certificate

Both sides prove their identity.
Simple explanation:
TLS: “Server, prove who you are.”
mTLS: “Server, prove who you are, and I'll prove who I am too.”
